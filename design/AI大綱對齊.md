## 已確認的生成契約

| 項目        | 原 worker 與 hono                                                |
| ----------- | ---------------------------------------------------------------- |
| 模型        | `@cf/openai/gpt-oss-120b`                                        |
| 請求格式    | `{ instructions, input }`；沒有指定額外生成參數                  |
| 單段 prompt | `請用正體中文把以下內容整理出來，重點整理。：`                   |
| 多段 prompt | `請為以下第${chunkIndex + 1}/${totalChunks}段內容生成重點摘要：` |
| 短文        | 不超過 15000 字直接送完整原文                                    |
| 分段        | 15000 字，先換行分段；過長段落按 `。！？` 分句並補 `。`          |
| 過長全文    | 超過 10 段時改以 30000 字分段，最多處理前 8 段                   |
| 合併        | 並行生成，依原順序加上 `## 第N部分`，沒有第二次模型整合          |
| 回應        | 取 `output` 最後一項的 `content[0].text`，略過前面的 reasoning   |
| 上傳輸入    | 兩者都在儲存用的 HTML 處理之前，把讀取的原文傳給生成函式         |

目前沒有模型、prompt 或分段設定偏離原 worker 的證據，因此保留原設定。
原 worker 中「使用 gpt-oss-20b 模型」的註解已過時，實際呼叫是 120b。

原 worker 會拒絕空字串結果，hono 的解析函式原本只確認結果是字串。
本次在大綱生成處補上空白檢查，避免空字串被當作成功結果，或在多段合併時被靜默略過。
失敗段會沿用原 worker 的失敗說明，其他段仍保留。

儲存時，原 worker 會編碼所有 HTML 特殊字元；hono 保留 Markdown 並編碼 `<`、`>`，
呈現時再清洗 HTML。這個差異不影響送給 AI 的原文或 prompt。

## 回歸驗證與品質驗收

`vp test src/tests/ai-summarize.test.ts` 驗證實際 AI 請求、分段邊界、並行合併順序、
Markdown 回傳，以及空白、格式錯誤和部分失敗的結果。測試使用 AI mock，
不依賴 sibling repo、帳號憑證或遠端模型。

這些測試確認搬移契約，不能證明模型實際生成的內容品質。
要確認使用者觀察到的品質落差，仍需以下同源對照：

1. 使用相同逐字稿原檔，確認兩個服務的已部署版本與工作區來源一致。
2. 比較單段原文與多段原文，記錄各段 AI 回應和合併後的大綱。
3. 比較議題涵蓋、事實忠實度、正體中文用語與 Markdown 結構，並確認是否有空白或失敗段。
4. 區分完整大綱與列表的 500 字預覽，並確認舊大綱是否曾被人工編輯。
